# ADR-006 - Database Migration Tool

| Status | Created Date | Decision Date | Updated Date |
|--------|--------------|---------------|--------------|
| Proposed | 28 Aug 2026 |  | 28 Aug 2026 |

## Context

StockFlow uses a modular monolith architecture with a single backend application and a shared PostgreSQL database.

- The database is separated into multiple schemas based on module boundaries
- Each schema should maintain its own migration history
- Database migrations for one schema should not depend on migrations from another schema
- Migrations should be easy to understand, maintain and execute in a predictable order
- A module and its database schema may be extracted into an independent service in the future
- The migration approach should therefore support both the current modular monolith and future service extraction without significant restructuring

## Options Considered

| Option | Description |
|--------|-------------|
| `Liquibase` | Provide different changelogs format and features such as rollback definitions, preconditions, contexts and labels |
| `Flyway` | Sequential version migrations and support for SQL-based migrations |
