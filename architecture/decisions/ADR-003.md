# ADR-003 - UUID or BIGINT

| Status | Created Date | Decision Date | Updated Date |
|--------|---------|---------|---------|
| Proposed | 12 Aug 2026 | 12 Aug 2026 | 12 Aug 2026 |

## Context

- Decide the primary key on each table in PostgreSQL

## Options Considered

| Option | Description |
|--------|-------------|
| `BIGINT` | All tables use `BIGINT` as primary ID |
| `UUID` | All tables use `UUID` as primary ID |
| `Hybrid` | `UUID` for public facing tables, `BIGINT` for internal tables |


## Comparison

| Option | Pros | Cons |
|--------|------|------|
| `BIGINT` | Shorter length (8 bytes) | Sequential and predictable |
|  | Smaller storage size | Harder to merge IDs from separate databases |
|  | Smaller indexes |  |
|  | Easy to read and debug |  |
| `UUID` | Globally unique | Longer length (16 bytes) |
|  | Harder to predict | Larger storage size |
|  |  | Larger indexes |
|  |  | Harder to read and debug |
|  |  | Harder to sort |
