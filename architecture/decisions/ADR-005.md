# ADR-004 - Container Deployment

| Status | Created Date | Decision Date | Updated Date |
|--------|--------------|---------------|--------------|
| Proposed | 13 Aug 2026 |  | 14 Aug 2026 |

## Context

- StockFlow will be packaged and deployed using containers
- The platform is expected to serve a relatively small number of merchants
- The initial deployment should be cost-effective and easy to operate
- The deployment environment should allow future scaling without introducing unnecessary infrastructure complexity
- The deployment strategy should balance cost, operational complexity, scalability, availability, and maintainability

## Options Considered

| Option | Description |
|--------|-------------|
| `Docker Compose on Single Host` | Deploy containers on a single host using Docker Compose |
| `Kubernetes` | Deploy containers on a self-managed Kubernetes cluster |
| `Amazon ECS or Amazon EKS` | Deploy containers using AWS managed container services |


## Comparison

| Option | Pros | Cons |
|--------|------|------|
| `Docker Compose on Single Host` | Low infrastructure cost | Single point of failure |
|  | Easy to deploy and operate | Manual scaling |
|  | Easy to reproduce locally | Downtime during host maintenance |
|  | Minimal operational overhead | Limited high-availability features |
| `Kubernetes` | Supports automatic scaling and self-healing | Higher infrastructure cost |
|  | Standard container orchestration platform | Requires Kubernetes knowledge |
|  | Suitable for large-scale systems | Higher operational complexity |
|  | Supports rolling updates | More components to manage |
| `Amazon ECS or Amazon EKS` | Less infrastructure management | Higher platform cost |
|  | Easier to scale | Increased dependency on AWS |
|  | Integrates well with AWS services | Less control over the underlying infrastructure |
