# ADR-004 - Authentication approach

| Status | Created Date | Decision Date | Updated Date |
|:---|:---|:---|:---|
| Proposed | 13 Aug 2026 |  | 24 Sep 2026 |

## Context

- StockFlow is designed as multi tenant system using modular monolith architecture
- Users belong to organisation and the resources must be isolated by tenant
- The organisation access control is controlled by Role-Based Access Control (RBAC)

## Options Considered

| Option | Description |
|:---|:---|
| `Self managed Bearer authentication` | Implement authentication directly with JWT access token and opaque refresh token |
| `Spring Authorisation Server` | Build a dedicated OAuth 2.0 and OpenID Connect authorisation server using Spring Authorisation Server. StockFlow operates as Resource Server |
| `Keycloak` | Keycloak manages the authentication and token lifecycle. StockFlow operates as Resource Server |
| `Authentik` | Use Authentik as Identity Provider and manages the user authentication and token issuance. StockFlow operates as Resource Server |


## Comparison

| Option | Pros | Cons |
|:---|:---|:---|
| `Self managed Bearer authentication` | - Full control of authentication and token lifecycle <br /> - Less infrastructure components | - Responsible for security handling <br /> - Need to implement and maintain authentication and token lifecycle <br /> - Custom implementation is needed if extra features in the future such as MFA, SSO |
| `Spring Authorisation Server` | - Standard OAuth 2.0 implementation <br /> - Spring ecosystem <br /> - Separate authorisation server and resource server responsibilities | - Require significant implementation and configuration <br /> - More complex than authentication embedded directly in the application |
| `Keycloak` | - Built in user, session and token management <br /> - Separate from StockFlow backend <br /> | - Additional infrastructure to deploy and operate <br /> - Need Keycloak specific configuration |
| `Authentik` | - Support SSO and OAuth 2.0 <br /> - Separate from StockFlow backend | - Additional infrastructure to deploy and operate <br /> - Smaller ecosystem and examples than Keycloak |
